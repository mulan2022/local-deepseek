# 本地 OCR 观察（开发版）

这部分尚未包含在 v0.1.12 已发布 APK 中。网页可保存开关与参数，
持续 OCR 和截图缓存由新的安卓客户端执行。

## 使用

1. 打开要接收观察记录的会话，进入「悬浮球」模式。
2. 点击悬浮球旁边的播放图标开始观察，完成安卓屏幕共享授权。观察时点击同一位置的暂停图标即可停止。设置页可调整采样和触发参数。
3. 切到视频或游戏。球可拖动，双击打开回复面板。新消息短暂显示气泡。面板的 `⋯` 菜单可预览截图或关闭悬浮球，左侧箭头返回完整聊天。模型需要相应服务商的 API Key。
4. 观察事件显示在原会话内，可以展开查看按图片 ID 和时间排列的 OCR 文字。

默认每次识别结束后等待 1 秒再采样，累计达到 **500 字**或首张待发送图片等待
15 秒时生成观察批次，**前提是已经出现符合条件的明显文字变化**。没有合格变化时，等待多久也不会通知 AI。字数是触发阈值，单张完整文字可能使批次超过阈值。
采样间隔、字数、等待时间和单行文字变化阈值均可修改；识别慢时不会堆积采样任务。

## 观察与取图

- OCR 使用随应用打包的 Tesseract4Android 4.9.0 和简体中文、英文 fast 模型，
  不需要 Google Play 服务或 OCR 云接口。OCR 本身不消耗模型 API Token。
- 在原分辨率图像上识字，逐行过滤低于 60 置信度、ASCII 符号过多、连续重复英文字母等识别噪声。
  中文标点、两字短句和“哈哈哈”保留，连串标点压缩为三个。
- 按行比较，不比较整屏。一行和已见过的每一行都相差达到单行变化阈值（默认 60%）才算新文字，
  还要连续两次识别到；置信度 80 以上且不少于 4 个字的行识别一次即可。短句可以累计，
  约 4 个新字（例如“你到哪了”）就算合格变化。数字、时钟、行序变化和短标签里错认一个字都不算；
  开始观察后的前两次识别只建立基准，画面运动或无字场景不会触发。旧默认 30% 首次升级为 60%，之后可自定义。
- 设置页的状态行显示已识别次数和新文字次数，便于判断是没识别到字，还是文字没有被判为变化。
- OCR 与 phone_capture 读取当前共享画面。悬浮球、回复框和键盘在取图时保持显示，
  按需取图可能包含这些界面。OCR 会过滤落在本应用悬浮区域内的文字，减少把自己的回复送回模型。
- 完整聊天界面在前台时暂停取图。请切到目标应用，或从悬浮回复面板的 `⋯` 菜单打开截图预览。
- 上传给会话模型的第一份内容只有文字、时间和图片 ID。图片按最长边 1280
  像素压缩为 JPEG 后缓存在本机内存中，最多 100 张、64MB。
- 模型调用 screen_get_images，通过 image_ids 选择本批次需要的 1–4 张图。
  支持视觉的模型直接接收截图。自定义 OpenAI 兼容中转也走直传，请选择能接收图片的模型。
  走识图回退的纯文本模型需要 DeepSeek Key，由 Flash 返回描述。
- 用户主动发送的消息优先。同一会话有回复或压缩正在运行时，OCR 批次排队；如果 OCR 已经在生成，
  暂停此次生成并保留原批次和图片 ID。用户这轮结束后，OCR 带着更新后的会话上下文重新发送。
  模型使用原会话的模型配置、记忆和已启用工具。
- 一个模型轮次进行期间或因用户优先而排队时，其批次图片不会被淘汰。本轮完成、失败或停止观察后清理
  该批图，期间采集的新图留给下一批。容量不足时先淘汰最老的未使用图片；
  已占满且全部正在使用时暂停加入新图。
- 图片 ID 不能跨批次、跨会话使用，过期时返回明确提示。OCR 文字和 AI 回复
  可以随聊天保存在 IndexedDB。未发送图片仅在临时缓存；已经发给模型的图片
  随实际请求留档，收藏后独立保留，见 [收藏说明](favorites.md)。
- 关闭观察、换观察会话、停止屏幕共享或进程结束会清除未处理的临时图片。

屏幕文字属于资料，不作为用户指令。游戏、视频中的文字也可能识别错误。
连续识别会增加耗电；细小弹幕、艺术字、快速字幕的识别率和采样速度需要真机测试。
开启自动观察后，批次通知、模型回复和按需识图仍可能产生 API 费用。

## 构建与验证

沿用 README 的 Android 打包脚本和参数。脚本会先运行
scripts/prepare-ocr.ps1，按固定版本及 SHA-256 下载 OCR AAR 与模型，
然后加入 Java 类、各 ABI 的原生库、模型及许可证；不依赖 Gradle。
首次下载需要网络，缓存位于忽略的 build/ocr/。
必要时可单独执行 scripts/prepare-ocr.ps1 并指定 -Proxy 参数。

纯 Java 缓存与文字门槛测试无需安卓设备：

    ./scripts/test-ocr.ps1 -Jdk 'C:/path/to/jdk'

另外运行 pnpm type、pnpm lint、pnpm build。
测试覆盖字数与时间触发、分批、100 张/64MB 上限、使用中图片保留、会话隔离及清理。
浏览器模拟桥接已验证文本先发、模型选图、无需图片时不取图、失败清理与忙时排队。
这些模拟测试不代表已验证真机 OCR 识别效果。

悬浮球手势、软键盘与实际游戏 OCR 质量仍需真机验收。文字门槛按模拟误识别调参，只出现一次且置信度不高的
快速字幕仍会漏掉；真机误触发偏多时调高单行变化阈值，仍嫌太少时调低。

网页桥接回归（先运行 pnpm build）：

```powershell
node scripts/tests/ocr-controls-browser.mjs dist
node scripts/tests/floating-ball-browser.mjs dist
```

涵盖悬浮球观察事件、关闭取消请求、批次排队与清理、静默回复不弹提示、260×200 网页布局、
草稿和上下文保留。小球本身的拖动与双击由安卓原生窗口处理，不属于浏览器测试范围。

## AI 控制

允许屏幕捕获且客户端支持 OCR 时，会话工具始终包含 phone_screen_observe，
action 为 start、stop、status；开启或关闭 OCR 不改动该工具和取图工具的定义。
开始操作绑定工具所属会话，使用当前参数且重复开始不重置基准；AI 无法自行获取
安卓共享授权，也不能接管其他会话正在运行的观察。用户按钮可请求系统授权。

用户停止时立即取消正在进行的观察回复；AI 在观察唤醒中调用 stop 时，立即停止采样，
但允许自己这轮的工具结果和简短回复完成。关闭屏幕捕获仍会取消该轮。
OCR 唤醒的模型说明要求通常一两句话，不复述整屏文字、旧回复或推理；
无有用新内容时只返回 HEARTBEAT_OK。会话的观察详情显示识别内容。

悬浮入口使用纯蓝色微动球体，旁边的播放图标开始观察，暂停图标停止观察。图标保留读屏说明和长按提示。动画在隐藏或离开窗口时暂停，遵循安卓系统动画设置。

第一次打开悬浮球时会显示手势教程。长按悬浮球录音，松手后才上传给 DeepSeek 转写并把文字作为独立消息发到当前会话。暂时无法发送时，转写文字放入草稿。首次使用需要安卓麦克风授权和 DeepSeek API Key。球上显示录音波形和转写进度动画。
